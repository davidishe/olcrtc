# OpenFlux-клиент (Cockney)

`internal/openflux` - L3-клиент транспорта OpenFlux через публичный документ Яндекс
Документов. Совместим по протоколу с exit node из
https://github.com/p1neappleXpress/OpenFlux (курсорные сообщения `18;<base64>`,
маркер `0x00`/`0x1F` + lz4). Используется в iOS-клиенте Cockney через
`mobile/openflux.go`.

Код написан ради диагностики, поэтому считает то, что upstream теряет молча:

- дропы очередей в обе стороны;
- кадры Яндекса с несколькими курсорами. Яндекс шлёт
  `{"type":"cursor","messages":[...]}`, а upstream берёт только первый курсор
  регуляркой;
- задержку доставки: локальное время приёма минус поле `time` из кадра;
- повторы TCP по номерам последовательности, отдельно для каждого направления;
- зонды `---KA---P1/R1`. Upstream их игнорирует как keepalive, а exit node с патчем
  Cockney отвечает на них, и по ответам считаются RTT и потери в каждую сторону.

До подтверждения авторизации (`auth result:1` или первый курсор) данные не
отправляются: Яндекс иногда закрывает сокет сразу после рукопожатия (`close 1005`).

Живая проверка против настоящего exit node:

```bash
OPENFLUX_DOC_URL=https://disk.yandex.ru/i/... go test -tags openflux_live -run TestLive -v ./internal/openflux
```

скопирован. Перед распространением в App Store это нужно перепроверить отдельно.
